Act I: The Problem

The industry reality

The #1 operational AI challenge

Enterprise AI token cost is this year's leading operational concern. Major consultancies and the business press are publishing on it in parallel.

Budgets exhausted in months

Companies are burning annual AI allocations in a fraction of the year, then rationing access to the tools they just standardised on.

$500–$2,000 per engineer / month

Cost per engineer at undisciplined usage. Multiply by seat count: the number is a fleet number, not a pilot number.

This is an engineering-behavior problem wearing a finance costume. Procurement cannot fix how a tool behaves inside a session.
Act I: The Problem

Why it happens

Optimized for done, not efficient

The tool's objective is completing the task. Nothing in that objective weighs what the completion cost.

No budget signal

The model cannot see spend. There is no institutional memory of what went wrong in last week's session.

No mechanical constraint

Written guidance is an input to reasoning, and reasoning under pressure routes around inconvenient inputs.

We demonstrated this empirically: the model was given explicit written instructions and violated them three times under task pressure, rationalizing around its own rules mid-session.
Act I: The Problem

The gap in current solutions

What platform governance covers

Agents deployed to production: what they may call, what data they may touch, how they are audited. Necessary, mature, and well-served by existing vendors.

What nothing covers

The developer's daily interaction with their own AI coding tool. That is where waste occurs: one session at a time, across every engineering seat.

Baton fills this gap. It governs the developer seat, the layer beneath deployed-agent governance, not a replacement for it.

Act II: The Methodology

What it enforces

Cost discipline
budget-guardDenies new spawns once a session crosses its token hard stop.
delegation-limiterForces every spawn to pin an allowlisted cheap model; caps concurrency.
session-timerNudges wrap-up once elapsed session time crosses a threshold.
worker-output-sizeWarns when a worker returns more text than the main context should carry.
session-routerClassifies each prompt's weight and injects a routing directive.
Security
credential-scannerBlocks credential-shaped strings in tool input and output; logs pattern, never value.
push-safetyBlocks force-push variants and rewritten-refspec pushes.
destructive-command-guardBlocks a fixed set of destructive shell patterns before they run.
Quality
context-managerWarns once per band as estimated context fill crosses a threshold.
task-drift-guardFlags a session that has drifted from the task it started on.
conductor-tripwireFlags the primary model doing hands-on work it should have delegated.
model-governanceRecords the baseline model, warns on a mid-session swap, checks an allowlist.
hook-health-checkSyntax-checks every installed hook at session start; warns, never blocks.
Thirteen hooks, three categories. Plain shell, roughly eighty lines each: fully inspectable, no black boxes.

Act III: The Proposal

How it deploys

One install command

A single script installs hooks, renders policy, and registers everything. Preview mode writes nothing.

Three profiles

Conservative, developer, research. Policy-driven configuration: thresholds and allowlists in YAML your org owns.

Merges, never overwrites

Existing configuration is preserved and backed up. Your other tooling keeps working untouched.

Fully reversible. One uninstall restores the original configuration byte-for-byte.
Reference implementation: Claude Code. The methodology and policy layer are tool-agnostic; the structure invites future runtimes.
